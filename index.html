Flag unusual traffic without a signature list.

AI-IDS is a local Python prototype with two traffic paths: repeatable synthetic attack simulations and optional passive capture of authorized IPv4 TCP/UDP packet metadata. An unsupervised Isolation Forest scores records and a Rich terminal dashboard presents review candidates.

    What the Python project does
    
    
    
      
    Learns what normal looks like
    An Isolation Forest (150 estimators) is fit on a normal-only baseline and scores new records by how easily they are isolated. No attack labels are used.
    
      
    Explains alerts
    In simulator mode, anomalies can be passed to a local Ollama model or a deterministic rule-based fallback. Live-capture outliers remain unclassified review candidates and are not sent for attack attribution.
    
      
    Simulates six attack types
    A traffic simulator mixes normal HTTP, HTTPS, SSH, and DNS records with six synthetic attack profiles so you can exercise the whole pipeline.
    
      
    Shows everything live
    A full-screen Rich dashboard displays packet counts, the alert feed, severity distribution, and protocol activity. Alerts and a session report are saved to disk.

    Simulated attack scenarios
    
    
    Run any of them with python main.py --attack <name>.
    
    
    
      
    ScenarioPattern the detector should find unusual
    
      
        
    Port scanSequential port activity from one source
    
        
    DDoS floodHigh-volume bursts of traffic
    
        
    Data exfiltrationUnusually large outbound transfers
    
        
    Brute forceRapid repeated authentication attempts
    
        
    C2 beaconPeriodic, beacon-like connections
    
        
    NULL scanPackets with no TCP flags set
    
      
    
    
    These are synthetic scenarios for demonstration. Detecting them in the simulator says little about performance on real traffic.
    
  
    

  
    
    
    Evaluation status
    
    
    
      
    Live detector: not yet evaluated on an independent, labeled benchmark dataset. The dashboard and live session reports therefore make no accuracy, F1, or false-positive-rate claims.
    
      
    Benchmark harness: available; results not yet produced or reviewed. The separate UNSW-NB15 runner in evaluation/ fits on normal-labeled training rows, calibrates on a normal-only validation subset, and reserves the official test split for final evaluation. This offline harness does not train or validate the live detector. No performance figures are claimed until the benchmark run completes and its JSON report is reviewed.
    
    
    
  
    

  
    
    
    Limitations
    
    
      
      
    • The browser experience is simulated. The Python application also supports passive IPv4 TCP/UDP metadata capture on an authorized interface through Scapy.
      • 
      
    • "Zero-day capable" means anomaly scoring can flag unseen patterns. It does not guarantee detection of real zero-day attacks.
      • 
      
    • Live mode starts with a fresh, untrained detector and learns from an operator-designated quiet window; it does not use the simulator's synthetic baseline. The quiet window is not independently verified as attack-free, and its held-out calibration tail is not an independent false-positive-rate measurement.
      • 
      
    • The separate UNSW-NB15 benchmark harness is available, but benchmark results have not yet been produced and reviewed; it does not validate the live detector.
      • 
      
    • Responses are proposals only. The application does not block IPs, isolate segments, or change firewall rules.
      • 
      
    • Retraining uses only samples explicitly marked as trusted-normal, and its effect on detection quality has not been measured.
